# Summary of phases

- Phase 1: Curate and standardize the genome dataset with multiple hosts.
- Phase 2: Identify host-associated accessory gene families (possible MGEs).
- Phase 3: Infer and characterize candidate MGEs.
- Phase 4: Map and validate candidate MGEs across validation collections.

This four-phase structure follows the analytical sequence in Maliha's proposal while retaining the detail of the original six-phase workflow as numbered subtasks.

## Phase 1: Curate and standardize the genome dataset with multiple hosts.

### 1.1 Define the discovery and validation datasets

Tools: Shovill

- Collect genome assemblies or sequencing reads from trusted collections. Possible trusted collections are DANMAP, NETHmap, Arizona, California, and Washington. (See Maliha proposal for details)
- If starting from sequencing reads, assemble each isolate with Shovill.
- Assign each collection to either the discovery dataset or the validation dataset before analysis.
- Include public surveillance collections in the validation dataset only where appropriate.

### 1.2 Apply genome assembly quality-control criteria

Tools: QUAST

- Retain genome assemblies that meet predefined thresholds for contig count, N50, and genome size.
- Record every excluded genome assembly and the reason for exclusion.

### 1.3 Standardize metadata across collections

Tools: Python (pandas)

- Standardize host, isolation context, geography, collection, and sequence type (MLST).
- Use the same host groups across all collections, for example human, chicken, turkey, pig, and cattle.

### 1.4 Standardize genome annotation

Tools: Bakta (v=xxx)

- Annotate all retained genome assemblies with the same Bakta version, database version, and settings.
- Produce standardized genome annotations for pangenome construction.

**Output:** Quality-controlled genome assemblies with standardized genome annotations and metadata, divided into predefined discovery and validation datasets.

## Phase 2: Identify host-associated accessory gene families

### 2.1 Construct the pangenome with PPanGGOLiN

Tools: PPanGGOLiN

- Cluster individual genes into gene families.
- Partition gene families into persistent and accessory gene families.

Persistent gene families occur in almost all genomes and mainly represent stable genomic functions. Accessory gene families occur in only some genomes and are more likely to represent host adaptation or mobile genetic elements.

### 2.2 Build the gene-family adjacency graph

Tools: PPanGGOLiN

- Record gene adjacency and gene order between gene families.
- Preserve the gene-family adjacency graph for Phase 3.

### 2.3 Test accessory gene families for host association

Tools: pyseer; mlst

- Use elastic-net models with cross-validation and population-structure adjustment.
- Use MLST-based lineage as the initial population-structure covariate.
- Test alternative population-structure covariates in sensitivity analyses if needed.

### 2.4 Select host-associated accessory gene families

Tools: pyseer; R (tidyverse)

- Retain accessory gene families with stable host association across cross-validation and sensitivity analyses.
- Report host-specific prevalence, effect size, cross-validation stability, and sensitivity to population-structure adjustment.

**Output:** A selected set of host-associated accessory gene families linked to the gene-family adjacency graph.

## Phase 3: Infer and characterize candidate MGEs

### 3.1 Extract the host-associated adjacency graph

Tools: PPanGGOLiN; Python (NetworkX)

- Select the host-associated accessory gene families from the gene-family adjacency graph.
- Retain direct gene adjacency and justified indirect links through intermediate gene families.

### 3.2 Define candidate MGEs

Tools: Python (NetworkX, pandas)

- Combine repeated gene adjacency observations into gene-family-level edges.
- Filter low-prevalence intermediate gene families and weak edges.
- Define each connected component of the gene-family adjacency graph as a candidate MGE.

### 3.3 Quantify candidate MGE host association

#### 3.3.1 Define candidate MGE presence

Tools: PPanGGOLiN; Python (pandas, NetworkX)

- For each genome assembly, calculate the proportion of constituent gene families that are present.
- Check whether the constituent gene families retain the expected gene adjacency.
- Define discovery-dataset presence criteria for complete and partial presence. The gene-family proportion and gene-adjacency thresholds will be selected with input from Dan and tested in Phase 4.

#### 3.3.2 Calculate prevalence

Tools: R (tidyverse)

- Calculate the prevalence of each candidate MGE in the discovery dataset.
- Calculate host-specific prevalence.
- Calculate prevalence when both gene-family presence and expected gene adjacency are required.

#### 3.3.3 Estimate host association

Tools: R (stats, broom)

- Compare each host group with all other host groups, for example chicken versus non-chicken.
- Use an adjusted logistic model:

      candidate_mge_present ~ host + MLST_lineage + geography

- Add collection as a covariate if the discovery dataset contains multiple collections.
- Report host-specific prevalence, prevalence difference, adjusted odds ratio, 95% confidence interval, FDR-adjusted p-value, and sample counts.

#### 3.3.4 Measure candidate MGE structure

Tools: Python (NetworkX, pandas)

- Measure gene co-occurrence, gene adjacency, number of constituent gene families, and adjacency-graph edge density.
- Flag candidate MGEs whose host association depends on one gene family or whose gene adjacency is not stable.

### 3.4 Characterize candidate MGEs

Tools: geNomad; MOB-suite; PhiSpy; ISEScan; IntegronFinder; MacSyFinder with CONJScan; Bakta; ISfinder, PlasmidFinder, and ICEberg as reference databases

- Characterize candidate MGEs using PPanGGOLiN co-evolving modules and constituent gene-family functions.
- Run sequence-based tools on the original genome assemblies, then compare their reported coordinates with the constituent gene families of each candidate MGE. Do not concatenate the constituent gene-family sequences into an artificial sequence.
- Use geNomad for plasmid and prophage evidence.
- Use MOB-suite for plasmid reconstruction, replicon typing, relaxase typing, and predicted plasmid mobility; use PlasmidFinder for additional replicon confirmation when needed.
- Use PhiSpy for additional prophage evidence when geNomad does not support a candidate MGE's prophage classification.
- Use ISEScan for complete and partial insertion sequences; use ISfinder to confirm insertion-sequence family assignments when needed.
- Use IntegronFinder for integrons.
- Use MacSyFinder with CONJScan for conjugative and mobilizable systems; use ICEberg as a reference database for integrative and conjugative elements.
- Use the tRNA and tmRNA annotations produced by Bakta as possible integration-boundary evidence.
- Prioritize candidate MGEs with strong host association, stable gene adjacency, and functions associated with mobile genetic elements.

The remaining tools in Text Box 1 can be used for targeted sensitivity analyses. DeepPlasmid, mlplasmids, and PlasFlow overlap with the primary plasmid tools; Phage Finder overlaps with geNomad and PhiSpy; TnpPred overlaps with Bakta and ISEScan; IslandPath-DIMOB, AlienHunter, and PAI-DB can support unresolved genomic-island candidates; AtlasT4SS and T346Hunter overlap with CONJScan; and tRNAscan-SE and Aragorn overlap with the RNA annotations already produced by Bakta.

**Output:** A catalog of candidate MGEs with their boundaries, constituent gene families, host association, structure, and biological characterization.

## (UNFINISHED) Phase 4: Map and validate candidate MGEs across validation collections 

### 4.1 Map constituent gene families with MMseqs2

Tools: MMseqs2

- Map the constituent gene families of each candidate MGE to the discovery and validation genome assemblies.
- Use documented identity, coverage, and e-value thresholds.

MMseqs2 produces sequence matches. Candidate MGE presence is determined by the presence criteria in Section 4.2.

### 4.2 Apply candidate MGE presence criteria

Tools: Python (pandas, scikit-learn)

- Apply the presence criteria from Section 3.3.1 to classify each candidate MGE as completely present, partially present, or absent in each validation genome assembly.
- Allow partial presence so fragmented genome assemblies are not automatically classified as absent.
- Measure classification confidence, sensitivity, specificity, and stability under alternative presence thresholds.

### 4.3 Test structural generalizability

Tools: R (vegan)

- Construct gene co-occurrence matrices within each validation collection.
- Determine whether gene co-occurrence and gene adjacency are retained across the discovery and validation collections.
- Flag candidate MGEs whose gene adjacency differs between collections for boundary refinement or sequence-level investigation.

### 4.4 Test host-association generalizability

Tools: R (metafor)

- Compare host-specific prevalence and adjusted odds ratios across validation collections.
- Quantify between-collection heterogeneity.
- Restrict host-association tests to collections in which the relevant host is represented.

### 4.5 Finalize the validated MGE catalog

Tools: SQLite; Python (FastAPI)

- Retain generalizable candidate MGEs as validated MGEs and label collection-dependent candidate MGEs explicitly.
- Store presence criteria, sequences, gene-family definitions, biological characterization, prevalence estimates, and validation results in a reproducible catalog or queryable database.

**Output:** A catalog of validated host-associated MGEs with presence criteria, uncertainty measures, and evidence of structural and host-association generalizability.
